| INV-003 | Oracle sandbox grants stay scoped to named subjects | Every grant in the oracle profile names what it applies to: reads only for the task worktree, the write box, the active runtime and the resolved command path; writes only for the box and two named devices; no unscoped IPC grant; and no read of another process. A class granted whole is narrowed by an explicit deny below it, because the imported system.sb grants classes this profile never names — withholding a grant is not denying one. Never a caller-supplied extra root. | Building or changing the oracle sandbox SBPL profile | sandbox._build_profile | The class-wide grants are a closed set — process-exec*, process-fork and sysctl-read — each argued. Spawning widens nothing, because a child inherits this same profile. sysctl-read is granted whole and then narrowed by the kern.proc deny, the runtime reading named kernel parameters at startup and failing os.uname() without them. Another process's argv and exec-time environment is admitted by EITHER process-info* or a per-pid sysctl, so each carries an explicit deny and is allowed back only along the axis that reaches no other process. A fourth class is a change to this invariant, not to the profile. | 1 | the out-of-worktree read, network-egress, Mach-service and unscoped-grant denial tests in tests/test_sandbox.py; test_another_process_environment_is_unreadable_from_inside_the_box, which reads a live victim's per-pid argv-and-environment blob from inside the box while proving the same read succeeds unconfined in the same run; and test_the_profile_grants_a_closed_set_of_classes_without_a_filter, which pins the class-wide set | a widened grant lets untrusted model code read ambient host files, reach the network, exfiltrate through Mach IPC that (deny network*) does not cover, or read the orchestrator's own exported API keys out of another same-uid process's exec-time environment | active |  |
| INV-004 | The repair tail carries no run-volatile fact | The distilled feedback tail contains only facts about the code under test; a fact about the run that produced it — wall-clock, absolute worktree path, host state — is stripped before the tail is built. | Building or changing the feedback tail fed back between attempts | PromptBuilder.distill_feedback | every consumer takes the tail from distill_feedback, which strips volatile fields at that single site; no caller assembles feedback from raw oracle output | 1 | the three distill_feedback determinism tests in tests/test_prompt.py: one unchanged failure distills identically across runs, an asserted duration inside a traceback survives, and two object reprs at different addresses distill identically | an unchanged failure asks a different question every run, so verbatim-repeat detection cannot fire and the benchmark cannot separate a better model from host load | active |  |
