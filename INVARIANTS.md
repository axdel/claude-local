| INV-003 | Oracle sandbox grants stay scoped to named subjects | Every grant in the oracle profile names what it applies to: reads only for the task worktree, the write box, the active runtime and the resolved command path; writes only for the box and two named devices; no unscoped IPC grant; and no read of another process. A class granted whole is narrowed by an explicit deny below it, because the imported system.sb grants classes this profile never names — withholding a grant is not denying one. Never a caller-supplied extra root. | Building or changing the oracle sandbox SBPL profile | sandbox._build_profile | The class-wide grants are a closed set — process-exec*, process-fork and sysctl-read — each argued. Spawning widens nothing, because a child inherits this same profile. sysctl-read is granted whole and then narrowed by the kern.proc deny, the runtime reading named kernel parameters at startup and failing os.uname() without them. Another process's argv and exec-time environment is admitted by EITHER process-info* or a per-pid sysctl, so each carries an explicit deny and is allowed back only along the axis that reaches no other process. A fourth class is a change to this invariant, not to the profile. | 2 | the out-of-worktree read, network-egress, Mach-service and unscoped-grant denial tests in tests/test_sandbox.py; test_another_process_environment_is_unreadable_from_inside_the_box, which reads a live victim's per-pid argv-and-environment blob from inside the box while proving the same read succeeds unconfined in the same run; and test_the_profile_grants_a_closed_set_of_classes_without_a_filter, which pins the class-wide set | a widened grant lets untrusted model code read ambient host files, reach the network, exfiltrate through Mach IPC that (deny network*) does not cover, or read the orchestrator's own exported API keys out of another same-uid process's exec-time environment | active |  |
| INV-004 | The repair tail carries no run-volatile fact | The distilled feedback tail contains only facts about the code under test; a fact about the run that produced it — wall-clock, absolute worktree path, host state — is stripped before the tail is built. | Building or changing the feedback tail fed back between attempts | PromptBuilder.distill_feedback | every consumer takes the tail from distill_feedback, which strips volatile fields at that single site; no caller assembles feedback from raw oracle output | 2 | the three distill_feedback determinism tests in tests/test_prompt.py: one unchanged failure distills identically across runs, an asserted duration inside a traceback survives, and two object reprs at different addresses distill identically. | INV-015 | The model server binds loopback only | The server's bind address is 127.0.0.1 and cannot be widened: not by a registry row, not by a FLAGS cell, not by a caller argument. mlx_vlm's own --host default is 0.0.0.0, so the address is always passed explicitly. | Building the model-server argv, or adding a FLAGS cell to a registry row | model_server.ModelServer.for_model | for_model is the sole builder of the server argv; it passes --host itself and exposes no host parameter, so a caller cannot widen the bind at the type level. The other two axes are runtime rather than type: a FLAGS cell smuggling --host is data the registry can express and is refused by a raise, and the builder's own loopback pair is held by tests — so this row's tier is that of its weakest axis, not its strongest. | 2 | tests/test_model_server.py asserts exactly one --host bound to 127.0.0.1, refuses a FLAGS cell smuggling it in three spellings (repeated token, --host= form, argparse abbreviation), and confirms the real registry flags still pass through | an unauthenticated local model server is published to every interface on the LAN from a data-only registry edit | active |  |
| INV-016 | A scored ladder survives every later fault | Once any case has been scored, no later harness fault may discard that score. Scoring completes before any side artifact is attempted, and a refused one — the style linter, the produced-code tree, the scorecard directory — costs only itself: the scorecard still prints, with a refused linter's count simply absent. Exit 3 then reports a broken host over a measurement that still stands, complete or partial alike. | Adding or widening a fault path in the benchmark harness | benchmarks/run.py main() | main() is the sole sequencer: score_cases runs before every artifact step, each of which is caught on its own, and an interruption reaches those same steps over the partial set it salvaged. Prose sites state the exit-code contract and cite D-BENCH-017 for the guarantee rather than re-enumerating the paths — re-enumeration is how this escaped twice on one branch, each newly added artifact fault landing while four prose sites still claimed exit 3 meant only the three pre-scoring faults. That prose axis is the weaker one and sets this row's tier: the sequencing is held by tests, but nothing mechanical pins a citation, so a re-encoding is caught only by a review-time derive-receipt. | 3 | tests/benchmarks/test_run.py drives main() to exit 3 through each of the three post-scoring faults — a broken style linter, a refused --code-out tree, a refused scorecard directory — and asserts each costs only its own artifact, never the ladder's scores | hours of decode already spent are thrown away because the host refused a side artifact, and the run reports only that it broke | active |  |
| INV-017 | A task's stable prefix is byte-identical across its calls | Every call in one task sends the same prefix bytes — rules card, spec, ordered context files, immutable test, and the frozen plan — and only the feedback tail differs. Nothing in that prefix may be recomputed, re-ordered or re-stamped per call. | Adding anything to the prompt prefix, or changing when the plan is computed | PromptBuilder.stable_prefix | stable_prefix is a pure function of the card bytes read once at construction, the TaskSpec, and the frozen plan; the plan is computed once per TASK by Loop._plan and passed in as an argument rather than recomputed per attempt (D-PROMPT-001). A per-call value reaching the prefix — a timestamp, an attempt number, a re-read card — is the violation, and it is invisible at runtime because the wrong bytes still produce a correct answer. | 2 | tests/test_loop.py asserts the attempt prefixes are byte-identical across two attempts AND contain the plan, so dropping the plan fails as loudly as mutating it; the plan call's prefix is a strict byte-prefix of the attempts'; a planning reply with no assistant content leaves the two byte-equal; and a counting builder pins it as assembled once per task, not per attempt. Byte-identity cannot cover no-re-stamp alone — a date stamp is constant WITHIN a run, so every assertion above still passes — so tests/test_prompt.py scans the MAXIMAL prefix (both optional sections supplied, because a section left defaulted is not scanned at all) for timestamp-like tokens, absolute paths and run ids, and a hypothesis property pins purity. Extending the prefix means extending that scan's lists, and reddens a differential test until docs/how-the-loop-works.html names the new section. | the server's prefill cache is discarded on every attempt, so the loop pays full prefill for the very bytes it was built to reuse — and nothing in the output reveals it, since the answers stay correct and only the decode cost moves | active |  |
