The version it prints is contract-version. | active |  |
| contract-version | dispatch | The cross-repo handshake string claude-local prints on --contract-version and claude-protocol compares to its own copy before dispatching: CONTRACT_VERSION at cli.py. | api-version, protocol-version, schema-version, cli-version | Versions the task-envelope schema and the exit-code map together, not the package: a release that changes neither leaves it untouched. | dispatch-cage | dispatch | The confinement an ORCHESTRATOR runs claude-local inside, whose only writable root is its isolation worktree — the reason a server log defaults to an unlinked temp file rather than a path. | orchestrator-sandbox, isolation-box, harness-cage | Not the oracle-sandbox, which claude-local builds around pytest and owns; this one is imposed from outside and claude-local only accommodates it. Keeps 'cage' meaning exactly one thing in code now that the oracle's confinement is uniformly the sandbox. | active |  |
| distilled-feedback | prompt | The repair brief fed back to the model in REPAIR mode: the complete file the previous attempt wrote, then the byte-capped, abs-path-stripped failure that file produced. The only part of the prompt that varies across attempts. | feedback, error-summary | Owned by prompt builder; isolated to the tail to preserve the stable prefix (D-PROMPT-001). Each section is capped independently so neither starves the other (D-PROMPT-003). | active |  |
| draft-model | serving | A small MTP model served alongside a large one for speculative decoding, named by the registry DRAFT column. | speculative-model, mtp, assistant-model | A row naming one does not mean its weights are present; Qwen3.8-27B declares one that is not pulled. | active |  |
| first-byte-deadline | generation | The wall-clock bound on a served model sending the first byte of a response, held by backend.HTTP_READ_TIMEOUT_S and enforced by the transport rather than by DerailGuard. | read-timeout, transport-bound, ttfb, pre-first-byte-window | The fourth deadline, and the only one no guard can see: a server binds its port the moment it starts but mlx_vlm faults weights in on the first inference request, so the wait before a stream begins is a lazy load, not silence. Measured by scripts/measure_first_byte.py at 50.1s cold for a 24 GB model, of which 9.1s was prefill. Must stay strictly greater than the guard's SILENT bound, so any gap the guard tolerates the socket tolerates too (D-DERAIL-004, amending D-DERAIL-003). The rejected read-timeout names the POLICY; httpx's own per-read mechanism keeps its own vocabulary at the transport leaf, as sandbox.py keeps a bare timeout_s — so 'httpx applies its read bound per read' describes the mechanism and is not drift, while 'the read bound expiring means the server went quiet' names this deadline and is. | active |  |
| generation-deadline | generation | The wall-clock bound on one producing decode, held by Budget.generation_timeout_s and enforced by DerailGuard as TIMEOUT. | timeout_s, decode-timeout, wall-clock-budget | Set generously: a slow model streaming steadily is healthy, and the SILENT bound is the hang detector, not this (D-DERAIL-005). | active |  |
| generation-params | serving | The per-model request-body fields a registry row's PARAMS cell declares, carried as ResolvedModel.generation_params and forwarded verbatim with every generation. | sampling-params, model-params, decode-params, inference-params, generation-config, gen-kwargs | Owned by the models.psv PARAMS cell and propagated to each front door by D-REGISTRY-004; non-thinking is one configuration reached through it, not a synonym, and generation_params_with is the only override path. | active |  |
| golden-app | model-evaluation | The complete reference application — the answer key the benchmark cases are carved from; each benchmark-case blanks exactly one of its golden files. |  | Rejected phrasings: reference app, golden application. The golden-tree is this same app's files served as read-only context; a golden-file is one file within it. | active |  |
| golden-file | model-evaluation | A correct answer-key file in the complete golden app, used as implementation or read-only neighbor context. | reference, solution | One golden-file becomes the target hole per benchmark-case. | active |  |
| harness-fault | model-evaluation | A break in the benchmark HOST rather than in the model's work: the run exits 3, distinct from exit 1's case that simply failed. | harness-failure, benchmark-error, harness-crash | Two classes, neither of which destroys a measurement already taken (INV-016, D-BENCH-017). Never the model's own failure: a model scoring 0/7 has been measured, and measuring it is what the instrument is for. | active |  |
| implement | entry-point | The owned public front door implement(spec, *, base_url, model, ...) -> Outcome that wires and drives the loop for one task; Outcome carries status, code, impl_path, files_changed, and the LocalEconomyRecord. | contract, builder-adapter, adapter, builder-api, plugin-interface, build | The single composition root (D-ENTRYPOINT-001, amended by D-ENTRYPOINT-004). Still the only front door that runs the loop, but no longer the only one: machine-cli adapts argv and stdin to it, and model-session serves and chats without it. | active |  |
| keep_only | editing | The writable allowlist: only the permitted impl path may be written, enforced by realpath containment under the worktree root. | allowlist, whitelist, path-guard | The oracle test is never in the writable set. | active |  |
| machine-cli | dispatch | The claude-local console script an orchestrator spawns: it reads one task-envelope, runs implement(), and reports the terminal status as its exit code. | cli, command-line-tool, bare-prompt-cli | The machine qualifier is load-bearing: D-ENTRYPOINT-001 rejected a bare-prompt CLI, and D-CLI-001 lifts that only for a CLI carrying a caller-supplied oracle test. | active |  |
| model-registry | model-provisioning | The committed table at models/models.psv: one row per model that MAY be served, naming repo, port, serving flags, and draft. | model-list, catalogue, catalog, models.psv, manifest | A claim about upstream; only the model-store proves what is on disk. | active |  |
| model-server | serving | The OS process serving one model over HTTP: python -m mlx_vlm.server, bound to loopback, alive only for the block that needs it. | server, backend, inference-server, endpoint | Distinct from backend, which is the transport TO it. Spawned by model_server, never through the oracle sandbox. | active |  |
| model-session | entry-point | The human front door: model_session(name) serves a resolved model for the duration of a with block and yields a callable that meters each turn, reaping the process on every exit path. | session, repl, chat, interactive-mode | The third entry point beside implement (the owned loop) and machine-cli (what an orchestrator spawns). It serves, which neither of the others does — the loop takes an already-running base_url — so it sits behind the optional serve dependency group (D-ENTRYPOINT-004). The rejected session names the CONCEPT; where a row or docstring has already established model_session as its subject, the bare noun is anaphora rather than drift — as "the server" is for model-server — so "kept warm for the session's whole lifetime" describes a turn and is fine, while "open a session against a served model" names this entry point and must qualify. A POSIX process session (start_new_session=True) is an unrelated homonym and keeps the OS term. The rejected repl likewise names this front door, never testing-methodology's live-test driver category, which keeps the term. | active |  |
| model-store | model-provisioning | The machine-local directory of weights actually pulled: one flat models/<NAME>/ per model, gitignored, outside any worktree. | cache, hf-cache, weights-dir, model-dir | Located by CLAUDE_LOCAL_MODELS; a missing dir raises ModelNotPresent, which is what blocks an accidental download. | active |  |
| non-thinking | generation | Generation with chain-of-thought suppressed for whole-file edit tasks, requested per model through its registry row's own PARAMS cell. | no-cot, direct-mode | No cross-model default: the request field that zeroes one model's reasoning is inert on another, so each row declares its own, and a hard thinking_budget rides only on rows whose soft request is known to work and that declare no draft model (D-THINKING-001, retiring the blanket default D-LOOP-002 had declared). | active |  |
| nudge | prompt | The escalation appended last to the volatile tail when an attempt stalls: the first failure's executed counterevidence, then one rung of a fixed ladder telling the model what to do differently | hint, prod, retry-instruction, reprompt, escalation-text | Owned by the prompt builder (nudge_for); the loop owns only the stall count that selects the rung. A function of that count alone, never of the run, so one unchanged failure still distils to one unchanged brief (INV-004). D-LOOP-005. | active |  |
| oracle-deadline | loop | The wall-clock bound on one sandboxed oracle run, held by Budget.oracle_timeout_s and bound into the kernel sandbox at the entry point. | timeout_s, sandbox-timeout, test-timeout | Stays tight: nothing legitimate takes long, and a non-terminating implementation is the failure it catches (D-DERAIL-005). | active |  |
| oracle-sandbox | oracle | The kernel confinement around pytest: scoped task/runtime reads, write-box-only writes, no network, bounded diagnostics, CPU/file-size caps, and process-group timeout teardown. | jail, cage, isolation-box | Fail-closed without sandbox-exec; D-SANDBOX-001 amended by D-SANDBOX-004. | active |  |
| oracle-test | oracle | The frontier-authored failing test that defines DONE; the model may never write it, and green means the task is complete. | spec-test, acceptance-test, gold-test | Immutable; pinned in the stable prefix (D-LOOP-001). | active |  |
| plan-first | prompt | One extra generation, before the first attempt, in which the model outlines its approach; the reply is frozen into the stable prefix for the rest of the task. | planning-mode, think-first, outline-pass, scratchpad | Not chain-of-thought by another name. Reasoning is decode the model emits INSIDE an attempt, which non-thinking disables under a hard cap because it is unbounded, unscored, and re-spent on every attempt; a plan is a separate bounded call whose output becomes PROMPT — read once, capped at 512 tokens, and byte-identical thereafter, so it costs decode once and rides the prefill cache forever after. Appended after the immutable test so the plan call's prefix stays a strict byte-prefix of every attempt prefix. Off by default: it changes what the model is asked, hence every measurement taken against it (D-PROMPT-002). Three values downstream, not two — plan-first, off, and unrecorded: a scorecard written before the field existed cannot claim either, so absent reads as unrecorded rather than off (D-TELEMETRY-003). | active |  |
| plateau | loop | Consecutive attempts whose oracle score never clears the best reached so far: the model writing different code that gets no further. | no-progress, flatline, score-stall | The quieter of the two stall shapes, and the commoner one — a loop watching only for byte-identical text spends its whole budget re-deriving one wrong answer. Two consecutive misses, not one: a single miss is a model still searching. Attempts that reached no oracle carry no verdict, so they neither break the streak nor extend it. Owned by loop._Plateau. | active |  |
| previous-attempt-source | prompt | The complete implementation file the previous attempt wrote and the oracle scored, carried in the repair brief so the model can correct the artifact the rules card tells it to correct. | prior-code, last-file, applied-source, model-output | The APPLIED bytes, never the raw reply - the raw reply carries fences and channel markup that are transport, not source. Capped separately from the failure (PREVIOUS_SOURCE_BYTE_CAP). | active |  |
| produced-code | model-evaluation | The tree of implementation files a benchmarked model wrote, saved by --code-out for post-hoc style scoring. | code-tree, saved-code, produced-tree, generated-code | Off by default and written outside the repository (.gitignore excludes code-*/), so it is never committed beside the scorecard that describes it — which is why a style_findings value from before --code-out existed is a frozen measurement, not a regenerable one (AC-PRODUCED). | active |  |
| readiness-probe | serving | The HTTP GET /v1/models poll ModelServer repeats until a spawned server answers, proving the process is up and bound. | health-check, liveness-probe, contract-handshake | Bounded by startup-deadline. Answering it proves only that the HTTP server bound its port: mlx_vlm faults weights in lazily on the first inference request, so a model reports ready seconds before it can generate, and the wait after that belongs to first-byte-deadline. Distinct from contract-handshake, which probes this package's own CLI rather than a served model — the two shared the undefined phrase 'readiness probe' across cli.py and measure_first_byte.py. | active |  |
| reasoning-delta | transport | One chunk of a model's chain-of-thought, delivered on its own wire field beside the reply rather than inside it. | thinking-token, thinking-delta, cot-chunk, thought-delta | mlx_vlm streams it as choices[].delta.reasoning_content with content null, and sends a duplicate 'reasoning' alias the decoder ignores. Metered and watched like content, never appended to the reply. Distinct from channel-transcript, which is markup INSIDE content. Captured at tests/fixtures/sse/reasoning_channel_stream.bytes. | active |  |
| repetition-loop | generation | A stuck decode state where the model emits the same large-n token slice consecutively; the derail guard's REPETITION trigger. | degeneration, stuck-state | Detected over a fixed deque window after warmup. | active |  |
| resolved-model | serving | One model-registry row resolved against the on-disk store into concrete locations: the weights path, the serving port, the mlx_vlm flags, the draft model, and the generation params. Carried as ResolvedModel; resolving never fetches, so a registered name whose weights are absent is refused here rather than downloaded. | resolved-row, model-spec, resolved-entry, model-config | Already first-class in four other primitives (a derived artifact in DERIVATION_MAP.md, the consumer of two owned resources in RESOURCE_OWNERSHIP.md, and named by the generation-params and model-session rows here), so it earns a row of its own rather than being described only through its neighbours. | active |  |
| rules-card-digest | telemetry | Short content hash of the exact rules-card bytes a run was given, stamped on every economy record and scorecard so two runs are comparable only when they agree on it. | card-hash, prompt-hash, card-version, card-id | Over the BYTES, never the path: implement() takes a rules_card_path override, so a path identifies a card only until it is repointed. Owned by PromptBuilder, the sole reader of those bytes. | active |  |
| rules_card | prompt | The static, token-budgeted engineering-rules card injected as the head of the stable prefix, byte-identical across a task's calls for KV-cache reuse. | system-prompt, guidelines, instructions | Static committed asset: src/claude_local/rules_card.md. | active |  |
| scorecard | model-evaluation | The comparable per-model aggregate of case correctness and local economy measurements. | report, result | Produced from per-case Outcomes. A PARTIAL scorecard is a real one: a harness-fault that interrupts the ladder still writes the cases that finished (D-BENCH-016), and cross-run comparison then refuses to RANK it against a full run rather than scaling it (D-COMPARE-001). | active |  |
| silence | generation | A stream that keeps a socket warm while delivering no content: the hang signal, bounded by SILENCE_TIMEOUT_S and reported as DerailReason.SILENT or backend.GenerationSilent. | stall, stalled, hang, quiet-stream | Named apart from stall deliberately — stall is the LOOP concept (an attempt that bought nothing) and reusing it here put two unrelated meanings under one word. Two layers report one thing because the guard's clock advances on chunk arrival, so a stretch with no chunks is the gap only the transport can see. | active |  |
| stable-prefix | prompt | The byte-identical prompt head (rules card + spec + ordered context files + immutable test) assembled once per task so only the feedback tail varies, preserving the server prefill cache. | prefix, system-prefix | Owned by PromptBuilder (D-PROMPT-001, amended by D-CONTEXT-001). | active |  |
| stall | loop | An attempt that bought nothing — the union of its two shapes: a verbatim-repeat (identical words) or a plateau (different words, no further). | stuck, spin, wasted-attempt | The umbrella the nudge ladder keys on: both shapes take the next rung, and the run ends when the ladder is spent. Named because the ladder must not care WHICH shape stalled — one counter walks it once, so termination is guaranteed by construction rather than by the model's cooperation. | active |  |
| startup-deadline | serving | The wall-clock bound on a spawned model server answering its first readiness probe, held by model_server.DEFAULT_STARTUP_TIMEOUT_S and named startup_timeout_s wherever a caller passes it. | boot-timeout, ready-timeout, spawn-timeout, timeout_s | One of five deadlines — beside generation-deadline, first-byte-deadline, oracle-deadline and sweep-ceiling — and one of the two bounding a PROCESS rather than a request. A bare timeout_s is rejected for the same reason its two Budget siblings reject it: with five deadlines in play the unqualified word names none of them. Fifteen minutes because a 27-31B model at 6-bit streams off disk on a cold load; the value is the largest any caller needed, not a guess. | active |  |
| style-finding | model-evaluation | One linter finding against a file a benchmarked model produced, attributed to the case that produced it: the quality number beside the oracle's correctness verdict. | lint-error, code-smell, quality-issue, style-violation | Measured over the produced-code tree, never inside the scorer, which reduces CaseResults already in memory. The scorecard is NOT a pure correctness record — the harness writes the count into its style_findings field while the tree is still there. score_style.py recovers the same number afterwards from a tree that was retained; null means not measured, 0 means measured and clean. Bounded to missing docstrings, missing annotations, and unused imports/variables/arguments; a guard against a state the code just made impossible has no linter rule and is invisible here. | active |  |
| sweep | model-evaluation | One pass over the whole registry: one benchmark-run per registered model, one resident at a time. Owned by scripts/benchmark_all_models.py, which prints every line under a [sweep] prefix. | batch, all-models-run, benchmark-run | Scoped to MODELS, never to cases: the per-model unit inside it is a benchmark-run, and conflating the two made 'a sweep is hours of decode' and 'a sweep measured 7/7 at 9858 tokens' name different things under one word. | active |  |
| sweep-ceiling | model-evaluation | The wall-clock bound on one model's whole chain inside a sweep, held by benchmark_all_models._PER_MODEL_CEILING_S. | timeout_s, per-model-timeout, sweep-timeout | The fifth deadline, and the second bounding a PROCESS rather than a request (beside startup-deadline). It exists so a model that HANGS costs its own row rather than the whole sweep, and it reaps the process GROUP because the child that matters is a grandchild — a server holding tens of gigabytes and the port the next model needs. Four hours is set well beyond a legitimate run, whose bounded worst case is already hours, so this is a hang backstop and never a budget. | active |  |
| task-envelope | dispatch | The JSON object a caller hands the machine-cli on stdin: impl_path, spec_text, test_text, expected_tests, budget, and optional context_files. | payload, task-block, job-spec, request | claude-local owns this schema; it is not the orchestrator's markdown task block (D-CLI-001). Server coordinates are deliberately not fields of it (D-CLI-002). | active |  |
| turn | entry-point | One interactive generation, metered on its own: a prompt in, text out, with no file applied and no oracle run — what one SessionHandle call produces. | interaction, exchange, prompt-round, chat-turn | Not a specialization of attempt (Rule 7): an attempt is generation plus apply plus oracle run, and a turn does neither, so a session fixes max_attempts at 1 and takes the sandbox's own oracle deadline as the inert placeholder Budget still demands. Distinct from the transport's logical call as well — total_calls is a ledger incremented at entry so it survives a mid-call raise, and it counts loop attempts and session turns alike, which is why SessionHandle.total_calls forwards that name rather than this one. _TURN_MAX_TOKENS and _TURN_GENERATION_TIMEOUT_S are the two caps bounding one. D-ENTRYPOINT-004. | active |  |
| unscorable-reply | loop | A reply the model completed that yielded no file to score: one carrying no whole-file frame, or one framed at a path outside the single writable one | unframed-reply, unusable-reply, blocked-attempt, no-edit-reply, tool-call-reply | Completion is the boundary: a server fault produced no reply and a derail killed one mid-flight, so neither is unscorable — both also score None, which is why the loop cannot key this on the absent score alone. Earns exactly one corrective re-ask carrying the reply back as counterevidence, then the nudge tail shape; spent once per run, so termination stays a property of the construction. D-LOOP-006. | active |  |
| verbatim-repeat | loop | An attempt whose generated text is byte-identical to the immediately preceding attempt's | replay, duplicate-attempt, repetition | One of the two shapes of a stall, and the louder one: under greedy decoding the same prompt yields the same file forever, so re-asking is arithmetic. Distinct from DerailReason.REPETITION, which is the guard catching a model repeating itself WITHIN one generation; this spans two attempts. It escalates rather than ending the run: it and a plateau both take the next rung of the nudge ladder, and the run ends when the ladder is spent (D-LOOP-005, amending D-LOOP-004). | active |  |
| whole-file-reply | editing | One model-produced implementation value carrying its declared target path and validated UTF-8 payload bytes. | fenced-reply, code-block, file-block | Framed on the wire by one FILE: line, a blank line, then the payload to the end of the reply; the header is exactly one line (D-EDITS-002). | active |  |
