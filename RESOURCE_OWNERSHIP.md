| http-timeout-bounds | transport | backend.HTTP_CONNECT_TIMEOUT_S and backend.HTTP_READ_TIMEOUT_S | Every consumer builds its own httpx.Timeout from the pair rather than typing the seconds — entrypoint and model_session on the loop's transport, and the probes under scripts/. measure_first_byte is the one partial consumer: it takes connect from the owner and supplies its own read bound, the value it exists to measure. derail's SILENCE_TIMEOUT_S comment assigns the first-byte deadline to the read bound by name; test_entrypoint asserts the read bound exceeds SILENCE_TIMEOUT_S | The read bound is measured rather than chosen — scripts/measure_first_byte.py is the probe it cites as its justification — so a second declaration would be a number with no measurement behind it. The two are a pair and only make sense together: connect is short because a refused local port fails at once, read is long because a cold weight load must fit inside it, so a consumer re-typing one would silently unpair them. Their ordering against the derail guard is pinned as an assertion in test_entrypoint, not left to a comment: SILENCE_TIMEOUT_S measures silence from the first byte, and the first-byte deadline before it is the read bound's to own (D-DERAIL-004). | active |  |

| model-store-env-key | registry | model_registry._STORE_ROOT_ENV (CLAUDE_LOCAL_MODELS) | Six dev scripts name it in their usage docstrings — benchmark_model, benchmark_all_models, probe_thinking_channel, capture_sse_fixture, measure_first_byte and e2e_local_model — so a reader learns the override without opening the registry. The exposure this row exists to name is prose, not code: a rename would leave six usage docstrings naming a variable nothing reads, each still perfectly readable, and no test would notice. Kept private for that reason — nothing outside model_registry has a use for the name, so publishing it would invite the second reader this row is written to prevent. | active |  |
| oracle-deadline | oracle | sandbox.DEFAULT_ORACLE_TIMEOUT_S | sandbox's own sandboxed_spawn timeout_s default; model_session's Budget; and the three dev scripts that build a Budget without running the oracle — probe_reply, capture_sse_fixture, measure_first_byte — plus the bundled quicksort example, each filling oracle_timeout_s from it. | One writer for the deadline the sandbox itself enforces, so the number and the code enforcing it cannot drift apart. Overriding stays per call rather than per copy: sandboxed_spawn takes timeout_s and every Budget carries its own, so a caller needing a different deadline states one instead of redeclaring the default. | active |  |

| server-startup-timeout | serving | model_server.DEFAULT_STARTUP_TIMEOUT_S | model session, as both its context-manager default and the module-level helper's; and the six serving scripts that spawn a server — benchmark_model, probe_reply, probe_thinking_channel, capture_sse_fixture, measure_first_byte, e2e_local_model — each as its --startup-timeout default. benchmark_all_models names the owner in prose instead of restating the number. | An owner that existed and was bypassed, which is why it is worth a row: before 01429c3 the constant read 480.0 while all seven scripts typed their own default — 600.0 in five, 900.0 in two — so the declared ceiling governed nothing it was supposed to.
