# Resource Ownership

## Ownership

| Resource | Area | Owner | Consumers | Enforcement | Status | Superseded By |
|-|-|-|-|-|-|-|
| LocalEconomyRecord | telemetry | telemetry module | loop (reads for LoopResult), contract (maps status) | single writer; orchestrator half owned externally | active |  |
| benchmark-worktree-lifecycle | model-evaluation | BenchmarkDriver | implement (pre-populated worktree), benchmark oracles | one managed temp directory per case; populate before implement and remove on every exit | active |  |
| best-passing-snapshot | loop | snapshot store | loop (restore on exit) | restore constrained by keep_only | active |  |
| bundled-rules-card-location | prompt | entrypoint.BUNDLED_RULES_CARD | implement (its default card), probe_reply, measure_first_byte | Resolved beside the package via Path(__file__).parent, so it holds for an installed package; a repo-root-relative copy would not | active |  |
| decode-rate-quotient | telemetry | types.mean_tokens_per_second | GenerationResult.tokens_per_second (per generation); LocalEconomyRecord.from_run (per task); benchmarks.harness.scorer.score_cases (per run, through the top-level re-export) | Sole site of the arithmetic AND of its zero-elapsed guard. The three consumers differ only in population — one generation, one task, one benchmark run — so each passes its own summed terms and none re-implements the quotient. The guard is what the single owner really buys: a second writer could return 0.0 where this one returns None, collapsing 'never measured' into 'measured at zero' in one layer but not the others (D-TELEMETRY-004). | active |  |
| generation-params | serving | the models.psv PARAMS cell, read once by ModelRegistry.resolve into ResolvedModel.generation_params | model_session, benchmark_model, probe_reply, e2e_local_model forward the resolved mapping; cli, benchmarks.run, examples.quicksort take it as --generation-params from whoever resolved it | one reader per declaration form, both in model_registry: generation_params_from_json for the flag and the PARAMS-cell parser for the row. A consumer forwards the mapping and never restates the fields; D-REGISTRY-004 | active |  |
| golden-authentication | model-evaluation | AuthService | security dependencies and benchmark oracles | password records and token signing centralized; accepted passwords reference validate_password; token carries user ID only; repository reload owns current role | active |  |
| golden-cron-semantics | model-evaluation | app.cron | ScheduleService and benchmark oracles | one parser and CronSchedule matcher; explicit UTC references; bounded calendar search; D-BENCH-008 | active |  |
| golden-database-schema | model-evaluation | app.db.initialize_database | repositories, application factory, benchmark oracles | DatabasePath is canonical; db owns DDL and cross-thread connection policy; app lifespan closes one connection; fresh path per case | active |  |
| golden-password-domain | model-evaluation | app.schemas.validate_password | UserCreate and AuthService | one validator rejects U+0000 before PBKDF2; D-BENCH-009 | active |  |
| golden-schedule-data-access | model-evaluation | ScheduleRepository | ScheduleService and benchmark oracles | parameterized schedule SQL; typed ScheduleRecord; field-local updates; no schedule SQL above repository | active |  |
| golden-schedule-policy | model-evaluation | ScheduleService | routers and benchmark oracles | one role-aware owner for schedule CRUD and disabled behavior; denied or missing operations never write; D-BENCH-010 | active |  |
| golden-user-data-access | model-evaluation | UserRepository | AuthService and benchmark oracles | parameterized user SQL; typed UserRecord; duplicate username translation; no user SQL above repository | active |  |
| impl-file | editing | edits.apply_file under keep_only | loop (reads), runner (reads) | paths.resolve_within realpath containment; oracle test excluded from writable set | active |  |
| keep_only | editing | paths.resolve_within | edits (apply), snapshot (restore) | single containment rule; rejects absolutes, resolves realpath, refuses symlinks, requires worktree containment | active |  |
| logical-call-ledger | transport | ModelClient._total_calls | loop (reads it onto the economy record), model_session (forwards the property as its own turn count), telemetry (carries it verbatim, never as len(results)) | single writer: a private attribute incremented at entry behind a read-only property, so a call that raised mid-stream is still counted; every consumer reads the owner and none recomputes the count from len(results) | active |  |
| model-id-slug | telemetry | telemetry.slug_model_id | LocalEconomyRecord.write, Scorecard.write, write_produced_code | one filename-safe slug for model ids; a shared literal has one owner (Deduplication Discipline) | active |  |
| model-registry-data | model-provisioning | models/models.psv | model_registry.ModelRegistry | Sole source of per-model repo, port, flags, draft; no second serving-config file. | active |  |
| model-reply-extraction | editing | edits.extract_file | loop (extracts one frame, then applies it) | one WholeFileReply with validated UTF-8 bytes; a single FILE: header line, then the payload to the end of the reply; keep_only validates the target (D-EDITS-002) | active |  |
| model-server-port-binding | serving | models/models.psv PORT column | model_registry.ResolvedModel.port | One port per model, distinct across rows; nothing else assigns a serving port. | active |  |
| model-server-process | serving | model_server.ModelServer.running | model session; the six serving scripts that spawn one — benchmark_model, probe_reply, probe_thinking_channel, capture_sse_fixture, measure_first_byte, e2e_local_model. NOT the machine CLI: cli imports no model_server at all, because BOUNDARY_MAP forbids it serving | Sole spawner, and sole ORDERLY killer: every consumer routes through the context manager, whose exit SIGTERMs the process group and escalates to SIGKILL after a grace period, so teardown is structural rather than remembered. One deliberate backstop overrides it — scripts/benchmark_all_models.py SIGKILLs a hung chain's whole process group when the sweep ceiling expires (D-SWEEP-003). | active |  |
| oracle-sandbox | oracle | sandbox.sandboxed_spawn | runner (default spawn) | deny-default SBPL; task/runtime reads only; write-box-only writes; no network; secret-free env; file-backed diagnostic tails; CPU/FSIZE and process-group timeout caps; fail-closed without sandbox-exec | active |  |
| produced-code-tree | model-evaluation | benchmarks.harness.produced_code.write_produced_code | benchmarks/run.py at both exits; scripts/score_style.py reads the tree | One writer for the whole tree, so the directory name always pairs with the scorecard's — same model slug, same run stamp — and a verdict is matched to the code behind it by name rather than by correlating mtimes. Both call sites are in run.py: --code-out saves it, and the default path writes to a scratch directory so style is measured even when the tree is not kept. A second writer would be a second naming scheme, which is how a style number gets attributed to the wrong run. | active |  |
| produced-edit-state | loop | LoopResult.has_scored_edit | entrypoint (maps Outcome code and files_changed) | derived from the scored best snapshot; seeded disk presence never counts | active |  |
| rules-card-digest | telemetry | PromptBuilder.card_digest | loop (stamps the record), LocalEconomyRecord, Scorecard, benchmark CLIs | The sole reader of the card bytes is the only thing that can name them truthfully; score_cases refuses a benchmark whose records disagree on the digest. | active |  |
| scorecard | model-evaluation | Scorer (score_cases, Scorecard.write) | benchmark run script, cross-model comparison | single writer; totals derived from CaseResult economy records, never re-counted; filename via telemetry.slug_model_id | active |  |
| scorecard-directory | model-evaluation | benchmarks.harness.scorer.DEFAULT_SCORECARD_DIR | benchmark_model (--out default), benchmark_all_models, compare_sweeps, score_style — all read it, none re-encodes the path | BOUNDARY_MAP declares scripts \| benchmarks.harness.scorer; the constant is anchored to benchmarks/ so no consumer needs a repo root | active |  |
| server-coordinate-env-keys | dispatch | cli.BASE_URL_ENV and cli.MODEL_ENV | the machine CLI itself, benchmarks/run.py, examples/quicksort/run.py — flag defaults, help text and error messages all read the constants | D-CLI-002 ratifies the CLAUDE_LOCAL_ channel; naming the keys once means a rename is one edit rather than three hand-edits with no compiler help | active |  |
| stable-prefix | prompt | PromptBuilder | loop (builds once), client (sends) | PromptBuilder is the single writer; feedback remains isolated to the tail. | active |  |
